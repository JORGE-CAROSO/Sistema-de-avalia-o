Sistema de Gerenciamento de Robôs

Contextualização

Uma empresa de tecnologia educacional desenvolve e utiliza diferentes tipos de robôs para atividades de automação, pesquisa e competições de robótica.

Com o aumento da quantidade de equipamentos, tornou-se necessário desenvolver um sistema para controlar os robôs disponíveis, seus responsáveis e suas características.

Você deverá desenvolver, em Java, uma aplicação capaz de cadastrar robôs, cadastrar operadores, listar os equipamentos e realizar operações com os robôs.

O sistema deverá utilizar os conceitos de Programação Orientada a Objetos estudados em aula.

1. Classes do sistema

O sistema deverá possuir, inicialmente, as seguintes classes:

  • Robô
  • Operador
  • Laboratório
  • Main

A relação entre as classes deverá ser representada por associação.

Operador ───────────► Robô controla Laboratório ────────► Robô gerencia

2. Classe Robo

Crie uma classe chamada Robo contendo os seguintes atributos privados:

  • • codigo
  • • nome
  • • tipo
  • • bateria
  • • ativo

Regras dos atributos

codigo: Deve ser um número inteiro positivo.

nome: Não poderá ser vazio.

tipo: Pode representar, por exemplo: Educacional, Industrial, Competição, Exploração.

bateria: Deve estar entre 0 e 100.

ativo: Indica se o robô está ligado/operacional.

Construtor

Crie um construtor parametrizado para inicializar todos os atributos:

Robo(int codigo, String nome, String tipo, int bateria, boolean ativo)

Utilize os setters para realizar as validações necessárias. A utilização de construtores parametrizados permite que o objeto seja criado já com suas informações iniciais.

Getters e setters

Crie os métodos de acesso para todos os atributos:

getCodigo() / setCodigo()
getNome() / setNome()
getTipo() / setTipo()
getBateria() / setBateria()
isAtivo() / setAtivo()

Os atributos devem permanecer private, utilizando getters e setters para consulta e alteração dos dados.

3. Métodos da classe Robo

ligar()

Crie: public void ligar()

O método deverá alterar o estado do robô para ativo. Entretanto, o robô só poderá ser ligado se possuir bateria suficiente. Caso contrário, exiba:

Não é possível ligar o robô.
Bateria insuficiente.

desligar()

Crie: public void desligar()

O método deverá desligar o robô.

recarregar()

Crie: public void recarregar()

O método deverá definir a bateria do robô como 100.

consumirBateria()

Crie: public void consumirBateria(int percentual)

O método deverá reduzir o nível da bateria de acordo com o percentual informado. O valor não poderá deixar a bateria abaixo de 0.

exibirDados()

Crie: public void exibirDados()

O método deverá apresentar todas as informações do robô. Exemplo:

--------------------------------
Código: 101
Nome: Robo Explorer
Tipo: Exploração
Bateria: 75%
Status: Ativo
--------------------------------

4. Sobrecarga

Implemente uma sobrecarga de construtores.

Além do construtor completo Robo(int codigo, String nome, String tipo, int bateria, boolean ativo), crie também:

Robo(int codigo, String nome, String tipo)

Nesse caso, considere que o robô será criado com:

  • bateria = 100
  • ativo = false

O aluno deverá demonstrar no main a criação de robôs utilizando os dois construtores. A sobrecarga deve possuir parâmetros diferentes; o tipo de retorno não é utilizado para diferenciar assinaturas.

5. Classe Operador

Crie a classe Operador com os atributos privados: codigo, nome, nivel.

O atributo nivel poderá representar: Iniciante, Intermediário, Avançado.

Crie: Construtor parametrizado; Getters e setters; Validação dos dados; Método exibirDados().

Método controlarRobo()

Crie: public void controlarRobo(Robo robo)

O método deverá receber um objeto Robo como parâmetro e apresentar:

Operador: Carlos
Código: OP01

Robô controlado:
Nome: Robo Explorer
Tipo: Exploração
Bateria: 75%

Aqui deverá ser utilizada uma associação entre Operador e Robo por meio de parâmetro de método.

6. Classe Laboratorio

Crie a classe Laboratorio. Ela deverá possuir:

private String nome;
private List<Robo> robos;

No construtor:

public Laboratorio(String nome) {
    this.nome = nome;
    this.robos = new ArrayList<>();
}

O ArrayList será utilizado para armazenar os robôs cadastrados no laboratório.

7. Cadastro de robôs

Crie o método: public void adicionarRobo(Robo robo)

Esse método deverá adicionar um objeto Robo ao ArrayList. Exemplo:

laboratorio.adicionarRobo(robo1);
laboratorio.adicionarRobo(robo2);
laboratorio.adicionarRobo(robo3);

8. Listar robôs

Crie: public void listarRobos()

O método deverá percorrer o ArrayList utilizando uma estrutura de repetição. Exemplo:

========== ROBÔS CADASTRADOS ==========

Código: 101
Nome: Robo Explorer
Tipo: Exploração
Bateria: 80%
Status: Ativo

Código: 102
Nome: Robo Edu
Tipo: Educacional
Bateria: 100%
Status: Desligado

Código: 103
Nome: Robo Challenge
Tipo: Competição
Bateria: 45%
Status: Ativo

9. Buscar robô

Crie o método: public Robo buscarRobo(int codigo)

O método deverá percorrer o ArrayList e retornar o objeto cujo código corresponda ao informado. Caso não encontre o robô: return null;

O método deverá possuir retorno, permitindo trabalhar a diferença entre métodos void e métodos que retornam valores.

10. Contar robôs ativos

Crie: public int contarRobosAtivos()

O método deverá percorrer o ArrayList e retornar a quantidade de robôs que estão ativos. Exemplo:

Quantidade de robôs ativos: 3

11. Tratamento de exceções

O sistema deverá possuir tratamento de exceções utilizando: try, catch, finally.

Crie no main um menu para interação com o usuário:

====================================
       LABORATÓRIO DE ROBÓTICA
====================================

1 - Cadastrar robô
2 - Listar robôs
3 - Buscar robô
4 - Ligar robô
5 - Desligar robô
6 - Recarregar robô
7 - Controlar robô
8 - Exibir quantidade de robôs ativos
0 - Sair

Digite uma opção:

O código responsável pela leitura e processamento da opção deverá utilizar try/catch. Por exemplo, se o usuário digitar abc quando o sistema espera um número, a aplicação deverá tratar o problema e continuar sua execução.

O InputMismatchException é usado justamente para situações em que a entrada não corresponde ao tipo esperado.

12. Uso do finally

O sistema deverá utilizar finally para informar que a operação foi finalizada:

Operação finalizada.

O finally deverá ser executado independentemente de ocorrer ou não uma exceção.

13. Situações que deverão ser tratadas

• Robô inexistente

Se o usuário pesquisar Código: 999 e não existir: Robô não encontrado.

• Bateria inválida

Se for informado Bateria: 150, o sistema deverá informar: Valor de bateria inválido. A bateria deve estar entre 0 e 100.

• Código inválido

Não deverá ser permitido cadastrar um robô com código menor ou igual a zero.

• Nome vazio

Não deverá ser permitido cadastrar um robô sem nome.

• Entrada incompatível

Caso o usuário informe texto onde o sistema espera um número, a exceção deverá ser tratada.
